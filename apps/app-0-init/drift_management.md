# Drift Management  
Canonical Standards for Detecting and Preventing Drift  
Maintained by Patch Governance Office

---

## 1. Purpose
This document defines the **canonical rules for drift detection, prevention, and correction** across all Patch‑universe artifacts.  
Drift is treated as a systemic failure mode, not a stylistic issue.

This file is an **operational contract**, not a narrative artifact.

---

## 2. Definition of Drift
Drift is any deviation from:

- canonical schema  
- codified ontology  
- deterministic templates  
- approved project flow  
- established character constraints  
- platform‑specific avatar rules  
- governance doctrine  

Drift may be **structural**, **semantic**, **visual**, or **behavioral**.

---

## 3. Types of Drift

### 3.1 Structural Drift
Occurs when:
- a schema is violated  
- a required field is missing  
- a field is added without approval  
- a template is modified without version increment  

### 3.2 Semantic Drift
Occurs when:
- character identity shifts  
- tone or archetype changes unintentionally  
- constraints are violated  
- responsibilities or capabilities contradict canon  

### 3.3 Visual Drift
Occurs when:
- character silhouettes change  
- avatar deviations collapse into the primary character  
- props, lighting, or palette violate established rules  

### 3.4 Behavioral Drift
Occurs when:
- avatars behave like full characters  
- characters adopt avatar‑like constraints  
- platform‑specific behaviors leak across platforms  

---

## 4. Detection Rules

### 4.1 Automated Checks
- Validate all JSON manifests against canonical schemas  
- Compare codices against templates for structural consistency  
- Detect missing or outdated version metadata  

### 4.2 Manual Review
Performed by:
- Patch Governance Office  
- Gordon, PPM  

Review includes:
- tone consistency  
- constraint adherence  
- ontology alignment  
- platform‑specific rule compliance  

### 4.3 Cross‑Artifact Comparison
Drift may emerge when:
- characters contradict each other  
- avatars contradict their primary character  
- flow definitions contradict codices  

All artifacts must be checked in relation to each other.

---

## 5. Correction Protocol

### 5.1 Minor Drift
Examples:
- wording inconsistencies  
- missing clarifications  
- minor visual note misalignment  

Correction:
- update artifact  
- increment MINOR version  
- log change  

### 5.2 Major Drift
Examples:
- ontology violations  
- schema violations  
- flow contradictions  
- character identity shifts  

Correction:
- governance review  
- update schema or codex  
- increment MAJOR version  
- update flow documentation (if applicable)  
- log change with justification  

### 5.3 Forbidden Drift
Examples:
- recursive avatar loops  
- collapsing character/avatar boundaries  
- unauthorized schema changes  

Correction:
- immediate rollback  
- governance escalation  

---

## 6. Prevention Rules

### 6.1 Schema Discipline
All artifacts must validate against canonical schemas before approval.

### 6.2 Template Discipline
All Markdown and JSON codices must be generated from canonical templates.

### 6.3 Versioning Discipline
All changes must follow semantic versioning rules.

### 6.4 Flow Discipline
All avatar and character relationships must remain DAG‑compliant.

---

## 7. Governance Responsibilities

### 7.1 Patch Governance Office
- Maintains drift rules  
- Approves corrections  
- Validates schema compliance  
- Oversees versioning  

### 7.2 Gordon, PPM
- Performs day‑to‑day drift detection  
- Flags inconsistencies  
- Enforces cadence and alignment  
- Escalates major drift
